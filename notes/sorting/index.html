ALGORITHMS / A SMALL FIELD GUIDE

Eight sorts.
One stubborn list.

Eight ways to put numbers in order. None can organise my desktop.

Each demo starts with the same 15 random numbers. Try your own list with Custom, then press Start. One demo runs at a time; the others are very good at waiting. Your numbers stay in your browser.

Reading the numbers: n is the list length; d is the number of digit passes; b is the bucket count. Stable sorts preserve the original order of equal keys. Extra space excludes the input but includes buffers and call stacks.

Code examples modify the supplied list of signed 32-bit integers. Demos also accept negative numbers and up to three decimal places. Animations explain steps rather than benchmark speed; radix digit reads are not neighbour comparisons.

01

Neighbourhood negotiations

Bubble sort

↑

Compare neighbours and swap the ones out of order. Repeat until nobody moves. Very sociable; less impressive when the guest list grows.

Best
O(n)
Average
O(n²)
Worst
O(n²)
Extra space
O(1)
Stable
Yes

The early-exit flag makes an already sorted list linear. Equal neighbours are never swapped.

02

One very deliberate choice

Selection sort

↑

Find the smallest remaining value and put it in the next position. Excellent at making decisions; determined to inspect everyone first.

Best
O(n²)
Average
O(n²)
Worst
O(n²)
Extra space
O(1)
Stable
No

It makes at most n − 1 swaps, but still scans the unsorted part every time. Swapping can reorder equal keys.

03

Make room for one more

Insertion sort

↑

Keep a sorted prefix, then slide each new value into its place. Like arranging playing cards, with slightly fewer accusations of cheating.

Best
O(n)
Average
O(n²)
Worst
O(n²)
Extra space
O(1)
Stable
Yes

A good fit for small or nearly sorted lists. The held value lives temporarily outside the displayed array while neighbours shift.

04

A little distance helps

Shell sort

↑

Insertion sort starts with distant neighbours, then closes the gaps. Some awkward conversations are easier to resolve from across the room.

Best
O(n log n)
Average
Gap-dependent
Worst
O(n²)
Extra space
O(1)
Stable
No

These examples halve the gap: ⌊n/2⌋, ⌊n/4⌋, …, 1. Bounds depend on that choice; there is no universal average bound for every gap sequence.

Divide, then politely reunite

Merge sort

↑

Merge small sorted groups into larger ones until the whole list agrees. Reliable teamwork, provided somebody brings an extra buffer.

Worst

Stable

These versions merge bottom-up and take the left value first on ties. The buffer uses linear space; no recursive stack is needed.

06

Everyone, pick a side

Quicksort

↑

Choose a pivot, partition around it, then sort each side. Usually quick; occasionally the pivot demonstrates poor leadership.

Best
O(n log n)
Average
O(n log n)
Worst
O(n²)
Extra space
O(log n) typical
Stable
No

These teaching versions use the last value as a Lomuto pivot. Sorted or equal-key input can cause quadratic work and O(n) stack space; the average assumes suitably mixed input.

07

The top bunk belongs to the largest

Heapsort

↑

Build a max-heap, move its largest value to the end, and repair the heap. A strict hierarchy, with surprisingly predictable deadlines.

Best
O(n) on equal keys
Average
O(n log n)
Worst
O(n log n)
Extra space
O(1)
Stable
No

The iterative sift-down stops when the parent is already large enough. Equal keys give linear best-case work; typical and worst-case work remain n log n.

08

Let the digits do the organising

LSD radix sort

↑

Group values by one byte at a time, from least significant to most significant. No neighbour debates, just an exceptionally organised filing system.

Best
O(d(n + b))
Average
O(d(n + b))
Worst
O(d(n + b))
Extra space
O(n + b)
Stable
Yes

These are four stable byte passes (d = 4, b = 256). Flipping the sign bit handles signed 32-bit order. The demo scales decimals by 1,000 first; its first counter records digit inspections.

#include <stdint.h>#include <stddef.h>#include <stdlib.h> /* Four stable byte passes; signed 32-bit integers, including negatives. */int sort_values(int32_t a[], size_t n) {    if (n < 2) return 1;    if (n > SIZE_MAX / sizeof(int32_t)) return 0;    int32_t *out = malloc(n * sizeof(*out));    if (!out) return 0;    for (unsigned shift = 0; shift < 32; shift += 8) {        size_t count[256] = {0};        for (size_t i = 0; i < n; ++i) {            uint32_t key = (uint32_t)a[i] ^ UINT32_C(0x80000000);            ++count[(key >> shift) & 255u];        }        for (size_t b = 1; b < 256; ++b) count[b] += count[b - 1];        for (size_t i = n; i > 0; --i) {            uint32_t key = (uint32_t)a[i - 1] ^ UINT32_C(0x80000000);            out[--count[(key >> shift) & 255u]] = a[i - 1];        }        for (size_t i = 0; i < n; ++i) a[i] = out[i];    }    free(out);    return 1;}

AFTER THE NUMBERS HAVE SETTLED

The best sort depends on the list.

Nearly sorted? Insertion may be perfectly happy. Need a stable guarantee? Merge has a spare buffer. Tight on space? Heap travels light. These are teaching implementations; standard-library sorts have considerably more experience.
